GitHub Copilot を agent mode で使うと、コードベースを調査し、変更を提案し、ファイルを編集してコマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ローカルマシンでリアルタイムに実行される各ツール呼び出しとファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または却下して、エディターを離れずに追加のプロンプトで会話を誘導できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムに監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントを誘導し、ハイコントラストモードに加えてライトモードの切り替えを追加します。

## シナリオ

[Exercise 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマを暗すぎると感じるユーザー向けに、ライトモードへの切り替えも追加したいとのことです。最初から新しい会話を始めるのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調査するファイル、実行するコマンド、提案する編集が表示されます。ファイル編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. Exercise 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択すると変更を適用します。
    - **Undo** を選択すると変更を元に戻し、もう一度作業するようエージェントに依頼します。
4. チャット上部にある **Files changed** インジケーターを開くと、このセッションでエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツール呼び出しに権限が必要な場合、エージェントは一時停止して **Allow** プロンプトを表示します。内容を確認し、許可できるコマンドのみ承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。実施した変更を要約する最終メッセージが表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードが完成したので、同じ会話を続けてライトモードの切り替えを追加します。同じチャットセッションを続けると、エージェントは、編集したコンポーネント、スタイルの方法、設定したローカルストレージのパターンなど、これまでの作業に関するコンテキストを保持します。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはこれまでの変更を調査し、ライトモードの追加を提案します。
3. ハイコントラストモードの場合と同じように、新しい編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. 期待しない方向に進んだ場合 (たとえば、好みではない方法で切り替え UI のリファクタリングを始めた場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を加えた追加メッセージを送ります。

> [!TIP]
> 進行中のセッションを誘導すると、最初から始めるより早く作業できます。追加プロンプトで調整を依頼できます (「CSS を簡潔にするため、セレクターの重複ではなく CSS 変数を使ってください」)、方向を修正できます (「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合してください」)、範囲を広げられます (「両方の切り替えにキーボードショートカットも追加してください」)。

## 変更内容をレビューする

コミットする前に、エージェントが変更した内容を一通り確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更ファイルをいくつか開き、差分を確認します。カスタムエージェントが指定したアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存) が適用されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。[次のレッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使って、進行中のセッションを監視し、誘導しました。ファイル編集を確認して承認または却下し、コンテキストを失わずに追加プロンプトを送信して作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムに監視しました。
- 個々のファイル編集を承認または却下しました。
- 追加プロンプトで進行中のセッションを誘導しました。
